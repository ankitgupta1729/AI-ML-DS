## 📖 About

This repository is a **single, curated home for everything I learn and build across the AI/ML/Data stack** — from the mathematical foundations of machine learning to shipping LLM-powered agents in production.

It is organised as ~45 numbered, self-contained modules. Each folder stands on its own: pick a topic, open it, and start running code. Nothing here depends on anything else, so you can dip in anywhere.

## 🚀 Getting Started

### Prerequisites

- **Python 3.11**
- **Git**
- Optional, per module: [Docker](https://docs.docker.com/get-docker/), [Go](https://go.dev/dl/), [uv](https://docs.astral.sh/uv/), a Java runtime for PySpark

### Clone the repository

```bash
git clone --recursive https://github.com/ankitgupta1729/AI-ML-DS.git
cd AI-ML-DS
```

> [`50-Andrew-Ng-Course-Material`](50-Andrew-Ng-Course-Material) tracks 17 upstream course
> repositories as git submodules, so `--recursive` is what fills those folders. Already cloned
> without it? Run `git submodule update --init --recursive`. To skip them entirely, clone
> normally and leave them empty — nothing else in the repo depends on them.

### Set up the base environment

### Launch the notebooks

```bash
jupyter lab      # or: jupyter notebook
```

> [!TIP]
> Several modules ship their **own** `Pipfile`, `requirements.txt`, or `pyproject.toml` (e.g. `20.LlamaIndex`, `23.LangChain`, `15.uv_demo`). Prefer the module-local environment when working inside one — it keeps dependency versions isolated and reproducible.

### Configure secrets

Modules that call external APIs read credentials from a local `.env` file — never commit it (`.env` is git-ignored).

```bash
cat > .env <<'EOF'
OPENAI_API_KEY=sk-...
ANTHROPIC_API_KEY=sk-ant-...
EOF
```

## 🧭 Conventions

- **Numbered folders** — the prefix reflects the order topics were added, not difficulty. Read them in any order.
- **Self-contained modules** — each folder holds its own notebooks, data, and (where needed) environment files.
- **Notebooks first** — exploration and teaching happen in `.ipynb`; reusable logic graduates into `.py`.
- **Commits** — short and descriptive; see [`AGENTS.md`](AGENTS.md) for the full contributor guide.

---

## 🤝 Contributing

Issues, corrections and suggestions are genuinely welcome — this repo gets better every time someone spots a mistake.

1. Fork the repository and create a branch: `git checkout -b feature/your-topic`
2. Keep new material inside a numbered module, or add a new one following the existing naming pattern
3. Clear notebook outputs before committing when they're large or contain secrets
4. Commit (`git commit -m "Add <topic> notes"`) and open a pull request

See [`AGENTS.md`](AGENTS.md) for repository guidelines and structure conventions.
